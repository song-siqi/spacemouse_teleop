### 已纠正的统计问题

旧 `value_changes` 直接比较整个 `values`，把其中 `received_at` 和 `sequence` 的变化计成了机器人或夹爪位置变化。现在仅比较实测量：关节 `joints_rad`、TCP `tcp_mm_rad`、夹爪 `position_pulse`；报告只比较其关节/TCP。目标、模式、状态码和所有时间元数据不参与判断。

重算后，所有上述静止阶段的实测位置变化次数均为 **0**。旧 report 的 299 次、夹爪的 1199 次“变化”均为元数据造成的误计，不能作为内部更新证据。工具同时输出数值变化间隔、排除小幅变化后的间隔和总体位移范围；这些阈值仅帮助检查证据，不是标定过的噪声模型，也不直接推断内部采样率。

旧工具没有在关闭数据文件前停止生产线程并排空尾部队列。历史文件没有完整关闭标记，无法追补可能未保存的尾部响应，故修正摘要保留 `historical_tail_drain_verified: false`。新版先停止/等待生产线程、排空队列、最后写 `profile_end`；阶段结束后才收到的在途响应保留在原始证据，但不计入阶段内速率。

## 接下来怎样补齐证据

1. 使用当前明确绑定的 `wrist/fixed_1/fixed_2`，在预览中确认各角色的实际内容。
2. 已有真实运动轨迹与旧基线对比；后续补机械臂和夹爪同时实际运动、跨 episode 准备/复位与异常场景。若单独运行只读旁路诊断且已有遥操夹爪 worker，保持 `--gripper-hz 0`，从既有日志提取夹爪反馈。
3. 对比 60 Hz 控制发送间隔、应答延迟、异常，以及去重后的状态变化时间。静止同值不判失败，微小噪声也不判作连续 20 Hz 新测量。即使看到与运动对应的变化，缺少设备内部时间时仍明确保留时间证据的限制。
4. 后续每个验收场景继续从完整共同区间核查必需来源、age、相机间时差、重复与丢帧、队列水位和磁盘吞吐；保持对尾部延迟的记录，不能只依据平均 Hz。当前阶段不要将尚未覆盖的并发动作或异常行为标为完成。

离线复查不会连接设备，示例：

```bash
spacemouse-xarm-frequency --analyze logs/collection_c0_20260909_run1 \
  --output logs/c0_reanalysis_new

  --control-log logs/MOTION_WITH_QUERIES.jsonl \
```

输出目录必须是新目录。`--control-log` 仅取与阶段重叠的遥操数据；基线使用指定文件中的遥操区间，复位行排除。应使用同一主机时钟时期的日志，不能把跨重启的 monotonic 值直接对齐。应答失败或诊断 worker 失败返回非零；不足 60 秒的阶段明确标记为非验收。
