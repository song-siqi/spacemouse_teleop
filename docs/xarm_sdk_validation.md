## 长按改为端点一次发送，核对目标覆盖

用户反馈小步方式仍动作不明显。`logs/xarm_demo_20260908T194754Z_214546.jsonl` 的位置范围 207–447，所有记录夹爪 error=0，最终正常 Ctrl-C 退出。一个持续约 0.45 秒的打开段，反馈从 289 到 321；受阻附近一次约 0.783 秒的打开段仍停在 208。记录可证明有位置变化，但不能把响应慢的原因全部归结于步长。

SDK 1.18.4 `_set_modbus_gripper_position(wait=False)` 的路径写入 `gripper_modbus_set_pos`，即位置目标寄存器；本项目的 codec 路径相同，不等待旧目标到位。新版按住打开只发送一次 850、按住关闭只发送一次 230；20 Hz 后续周期只读取反馈、校验输入期限。同方向每次输入续期不会重写目标；松开时以当前位置替换目标，反向时写另一端点。移除两套真机 JSON 的 `jog_speed_pulse_s`，保留 SDK 设备 speed=500 与传感器闭合下限。启动不发送位置目标。

新增 `target_sequence` 日志字段（终端 `goal_seq`）统计成功发送次数，以及只读 `controller_target_pulse`（终端 `device_target`），使用相同位置目标寄存器的两寄存器读取并验证响应。目标读回在每轮发送前完成，因此新指令通常下一轮才反映在读回值中。19:56:37 UTC 实机只读结果：位置 408、设备目标 407、status=0 stopped、error=0；机器人 state=4、mode=5、error/warn=0。

81 项真机/输入测试通过（0.539 秒）。覆盖持续输入续期只发一次、到端点后不重发、松开替换未完成目标、释放后重新按住、反向、输入超时、退出、传感器边界、真实 SDK 编解码及目标读回。0.5 秒 mock dry-run、脚本语法、diff 检查通过；未追加 MuJoCo 检查。物理打开/关闭和释放停止仍待验证，fake 模型不证明固件的实际停止响应。

与小步版相比，断连后的最大剩余行程变为端点剩余行程：夹爪位置指令没有控制器有效期；进程被强制终止或网络故障时，软件保持可能无法送达，已发送端点仍可能完成。独立线程保证机械臂无需等待夹爪运动，但这不等同于夹爪断连即停。

## 延长复位上限并处理反馈到期前的发送预算

两套独立真机配置 `robot.homing.timeout_s` 从 30 秒改为 120 秒；关节速度 0.1 rad/s、加速度 0.2 rad/s² 不变。该时限与复位结束后才开始的遥操 `--duration` 独立。

现有日志 `xarm_demo_20260908T195725Z_215226.jsonl`、`xarm_demo_20260908T195734Z_215242.jsonl` 的复位分别在约 4.8 秒、9.0 秒失败，原因都是 `Velocity command expired before send`，未记录用尽 30 秒的复位。失败前最后发送时反馈年龄约 0.185/0.183 秒，扣除 0.05 秒通信预留后仅剩约 0.015/0.016 秒速度有效期；后续发送可能已无有效预算。

复位循环现重新计算反馈剩余有效期，在不足通信预留加一个循环周期时等待下一报告，而不是尝试发送接近过期的命令；记录 `homing_waiting_feedback`。每次等待仍检查总复位时限、输入和反馈，真正反馈过期仍故障停止，控制器上的有限速度有效期不延长。此调整仅作用于复位循环。

83 项真机/输入测试通过（0.586 秒）。新增 fake 环境按真实有效期使速度自动失效，模拟 0.205 秒报告间隔，验证较远关节从 3.2 rad 复位耗时超过 30 秒仍在新时限内完成；也验证等待期间报告停止后仍在原反馈超时附近退出。测试不连接机器人、不运行 MuJoCo。较远真实姿态的复位仍待用户下一次启动验证。


## 复位第一步自动打开夹爪

用户要求释放上一轨迹末尾可能仍夹持的物体后再 reset。启用夹爪时，`XArmBackend.home` 现先执行独立打开阶段：检查现场参数/机器人与输入状态，初始化工具通道、发送一次 `open_pulse`，读取实际位置、设备目标和运动状态，确认完成后才建立可写机械臂通道、使能并进入 Mode 4 关节复位。打开期间不发送机械臂使能、模式或速度指令。禁用夹爪的配置保持仅机械臂复位；诊断和 dry-run 不发送新动作。

两套独立真机 JSON 新增 `gripper.startup_open`：timeout_s=10、tolerance_pulse=15、settle_s=0.2。到位要求实际位置和设备目标均在配置打开目标 ±15 pulse 内，且 stopped 连续维持 0.2 秒；容差基于本机发送 850、读回 840、实际停在约 838 的既有数据。不会仅凭 ACK、仅凭 stopped 或抓取状态判定完成。

打开失败、超时、报错、输入/反馈故障或中断时尝试保持夹爪当前位置并退出，阻止启动机械臂复位。成功后关闭准备阶段的工具通道，进入机械臂复位；遥操阶段仍用独立 worker 控制夹爪。夹爪位置目标无控制器有效期的既有通信限制仍适用，保持指令无法送达时不能保证夹爪停止，但本流程不会继续启动机械臂。
